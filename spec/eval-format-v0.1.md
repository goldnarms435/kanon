# Kanon Evaluation Format Spec — v0.1

**Status:** Draft for review.
**Owner:** Epikuru Technology.
**License:** Apache-2.0.

This document defines the on-disk format for Kanon evaluation cases. Each case is a single YAML file. The format is designed to be:

- **Self-contained** — one case per file, fully reviewable on its own.
- **Version-stable** — additive changes only across patch versions.
- **Vendor-plural** — IOS / NX-OS / Junos / FRR / SRL configs all accepted in `context`.
- **Reproducibly scored** — every case declares its scoring contract.

---

## File location and naming

```
/cases/<category>/<case-id>.yaml
```

- `<category>` mirrors the `category` field below.
- `<case-id>` follows pattern `<category-short>-NNN`, e.g., `bgp-001`, `evpn-004`.
- IDs are immutable once published. Retired cases keep their ID and set `status: retired`.

---

## Required fields

| Field | Type | Notes |
|---|---|---|
| `id` | string | Globally unique. Pattern: `^[a-z]+-[0-9]{3}$`. |
| `version_introduced` | string | Kanon version case first appeared in. e.g., `0.1`. |
| `category` | enum | See **Categories** below. |
| `difficulty` | enum | `basic`, `intermediate`, `advanced`, `expert`, `edge-case`. |
| `tags` | list[string] | Free-form technical tags (e.g., `med`, `route-reflector`, `type-2`). |
| `prompt` | string (block) | The question presented to the model. Stable wording. |
| `scoring` | object | See **Scoring** below. |
| `reference_answer` | string (block) | Canonical human-expert answer with reasoning. |
| `author` | string | Initial author. |
| `created_at` | string (date) | ISO 8601. |

---

## Optional fields

| Field | Type | Notes |
|---|---|---|
| `subcategory` | string | Free-form refinement of `category`. |
| `context` | string (block) | Configs, topology snippets, `show` output. Multi-vendor allowed. |
| `common_wrong_answers` | list[object] | Each: `answer`, `why_wrong`. Used by judges and for documentation. |
| `references` | list[string] | RFC numbers, vendor doc URLs, IEEE specs. **Never** paid material. |
| `reviewed_by` | list[string] | Reviewers who validated the answer key. |
| `contamination_set` | bool | `true` = held out from public release. Default `false`. |
| `status` | enum | `active` (default), `retired`, `under-review`. |
| `updated_at` | string (date) | ISO 8601. |
| `notes` | string (block) | Maintainer commentary, not shown to models. |

## Categories

v0.1 supports six. New categories require a spec PR.

| Category | Short code | Description |
|---|---|---|
| `bgp-path-selection` | `bgp` | BGP best-path decision process and its toggles. |
| `evpn-route-types` | `evpn` | EVPN NLRI semantics, Type-1/2/3/4/5 reasoning. |
| `evpn-troubleshooting` | `evpn` | EVPN operational symptom → root-cause cases. |
| `config-bug-hunt` | `cfg` | Identify the bug in a provided config. Multi-vendor. |
| `fabric-design` | `design` | Leaf-spine and DC fabric design under constraints. |
| `symptom-rootcause` | `rca` | General networking RCA + diagnostic ordering. |
| `protocol-theory` | `theory` | IGP/BGP/L2 edge-case theory. |

## Scoring

Every case declares one of four scoring types:

### 1. `multiple_choice`

```yaml
scoring:
  type: multiple_choice
  choices:
    A: "Route A wins on lower MED."
    B: "Route B wins on shorter AS-path."
    C: "Route A wins on higher Local Preference."
    D: "Route B wins on lower router-ID."
  correct: B
```

Scored exact-match on the choice letter. Models are instructed to answer with the letter only.
The runner prompt requires the first response line to contain exactly one choice
letter; explanatory prose may follow on later lines.

### 2. `exact_match`

```yaml
scoring:
  type: exact_match
  accepted_answers:
    - "Type-2"
    - "Type 2"
    - "MAC/IP advertisement"
  case_sensitive: false
  match: substring   # or "equals" or "regex"
```

Scored by string match against any accepted answer.

### 3. `rubric`

Free-form answers scored by an LLM judge against a structured rubric.

```yaml
scoring:
  type: rubric
  judge: claude-opus
  judge_prompt_ref: rubrics/standard-rubric-v0.1.md
  criteria:
    - id: identifies_root_cause
      weight: 40
      description: "Identifies that the Type-2 advertisement is not being generated by Leaf-2."
    - id: correct_diagnostic_sequence
      weight: 30
      description: "Proposes checking the local MAC table on Leaf-2 before checking BGP tables."
    - id: notes_rt_mismatch_possibility
      weight: 15
      description: "Mentions RT/RD mismatch as a candidate cause."
    - id: avoids_false_causes
      weight: 15
      description: "Does not propose physical-layer or IGP causes when iBGP session is up."
  max_score: 100
  pass_threshold: 70
```

Weights sum to `max_score`. Judge prompts published in `/rubrics/`.

### 4. `structured`

For multi-part answers requiring specific data points (used sparingly).

```yaml
scoring:
  type: structured
  required_fields:
    - field: route_type
      accepted: ["Type-2", "Type 2", "MAC/IP"]
      weight: 25
    - field: esi_value
      accepted: ["0", "all zeros", "single-homed"]
      weight: 25
    - field: ip_length
      accepted: ["32", "/32", "host route"]
      weight: 25
    - field: ethernet_tag_id
      accepted: ["0"]
      weight: 25
```

If `pass_threshold` is omitted, the runner uses `70%` of the summed field
weights. Cases may override this with an explicit `pass_threshold` when exact
completion is required.

## Difficulty levels

| Level | Definition |
|---|---|
| `basic` | First-month-on-the-job. Tests fundamentals. |
| `intermediate` | CCNP-grade. Solid working knowledge. |
| `advanced` | CCIE-written-grade. Multi-attribute reasoning. |
| `expert` | CCIE-lab-grade. Edge cases, decision-process traps, multi-vendor nuance. |
| `edge-case` | RFC corner cases, vendor-implementation divergence, deliberate gotchas. |

Target distribution for v0.1 public set: 10% basic, 25% intermediate, 35% advanced, 25% expert, 5% edge-case.

---

## Contamination set

~25% of cases are flagged `contamination_set: true` and held out of the public repo. Released only to commit-trusted reviewers. Scores reported separately as public-set and held-out-set. Public–private divergence > 15 points flags suspected training-set contamination.

---

## Versioning

- **Major** (`1.0`): breaking format changes. Cases may need migration.
- **Minor** (`0.2`): new fields, new categories, new scoring types. Additive only.
- **Patch** (`0.1.1`): new cases, answer-key corrections.

Every case carries `version_introduced` so leaderboard runs can be reproduced against historical subsets.

---

## Contributor checklist

Before submitting a case PR:

- [ ] `id` follows pattern and does not collide with existing cases.
- [ ] `prompt` is self-contained — does not require external context the model cannot infer.
- [ ] `reference_answer` cites a public source in `references` (RFC, vendor public doc, IEEE).
- [ ] No content lifted from paid training material (Cisco Press, INE, CBT Nuggets).
- [ ] At least one `reviewed_by` entry from a credentialed reviewer (CCIE / JNCIE / equivalent).
- [ ] `common_wrong_answers` populated where models are known to fail.
- [ ] If `rubric` scoring: criteria are objective and testable, weights sum to `max_score`.
